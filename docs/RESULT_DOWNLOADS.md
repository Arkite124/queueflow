# 결과 다운로드와 드래그 업로드

완료 작업의 파일 및 보고서 영역에서 다음 기능을 제공한다.

- 결과 일괄 다운로드: `cleaned.csv`, `errors.csv`, `summary.json`, `report.xlsx`를 담은 `results.zip`.
- Excel 요약 보고서: 처리한 행, 결과 CSV 행, 오류가 있는 행을 한글 표와 숫자 형식으로 표시한 `report.xlsx`.
- 기존 CSV/JSON 개별 다운로드는 유지한다. 보존기간이 지난 결과에는 새 버튼도 표시하지 않는다.

Excel과 ZIP은 저장된 확정 결과를 읽어 요청 시 생성하므로 이전 완료 작업에도 적용된다.
다운로드를 위해 DB/worker 상태나 결과 파일을 변경하지 않는다. 새로운 DB 스키마는 없다.
ZIP에는 원본 CSV를 포함하지 않는다. 생성 중 큰 ZIP은 임시 디스크로 넘기고 응답 종료 시 닫는다.

새 API:

```text
GET /api/v1/jobs/{job_id}/exports/results.zip
GET /api/v1/jobs/{job_id}/exports/report.xlsx
```

기존과 같은 소유자/세션 검사를 적용한다. 타인 작업 404, 비로그인 401,
보존기간 만료나 파일 소실 410, 아직 결과가 없으면 404다. ZIP 내부 파일명은 서버의 고정 이름이다.

업로드 영역은 CSV 한 개를 끌어놓거나 파일 선택으로 추가할 수 있다.
두 방식에 같은 확장자/빈 파일/20 MiB 검사를 적용하며 업로드 중에는 선택을 바꾸지 않는다.
실제 CSV 내용과 행 수는 기존 서버 검사를 그대로 사용한다.

## 운영 반영

프런트와 API를 함께 배포해야 새 다운로드 URL이 동작한다. main 병합/푸시 및 운영 API 재생성은 별도 승인이 필요하다.
Excel 의존성 추가로 API 이미지를 다시 빌드해야 한다. 기존 작업/볼륨을 보존한다.
OS 예약 작업이나 기존 Tunnel은 변경할 필요가 없다.
